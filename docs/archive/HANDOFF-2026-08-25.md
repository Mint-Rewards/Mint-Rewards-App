## MANUAL QA OWED (cannot be done from this environment)

On a device/simulator:

**Task 1 — pin state**
1. Open editProfile map with no saved pin → GPS centers the camera, **no marker appears**,
   Confirm stays disabled.
2. Tap/drag → marker appears, Confirm enables.
3. GPS re-center after placing a pin → camera moves, **marker does not**.
4. Save without a pin → blocked with "Please pin your exact location on the map".
5. Existing user with saved coordinates → marker shows at saved spot, confirmable as-is.

**Task 2 — pickers**
6. City field searches all cities; there is no province step anywhere on the screen.
7. Picking a *different* city clears town + sub-area; re-picking the *same* city does not.
8. Town field searches, still offers "Other" → free text → back-to-list button.
9. A DHA town labels the sub-area field "Block" (not "Sub-area").
10. Save a city-picked profile → the user does NOT get re-prompted by the
    location-update prompt, i.e. `province` persisted correctly.

**Task 4 — analytics** (PostHog live events view)
11. `map_opened` once per open, with `viewportSource` = saved_pin / device_gps / default
    (deny permission to see `default`).
12. `pin_interacted` per tap/drag with an incrementing `dragCount`.
13. `flow_abandoned` on closing with X, but **not** after Confirm.
14. `location_saved { source: "map_pin", precision: "building" }` once per save of a
    freshly placed pin.

**Task 3 — backend round trip**
15. With the backend on `feature/location-capture-p0`, save a profile and confirm
    `structuredAddress` + `location` land on the user document, and that a town change
    clears the previous town's `blockId`.
